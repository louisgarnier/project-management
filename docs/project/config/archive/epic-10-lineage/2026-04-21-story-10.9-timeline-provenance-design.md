# Story 10.9 — Timeline Item Provenance + Ancestor Visualization — Design

> **Goal:** In the Topics Timeline, surface item-level provenance (which call first contributed each follow-up / decision) and make M:N-merged topics' archived-ancestor history visible as indented, tree-nested rows attached to their merge-result row.

**Status:** Design — 2026-04-21
**Epic:** EPIC-10 — Topic Lineage + Full-Stage Traceability + Prompt Quality
**Story:** 10.9
**Depends on:** 10.1 (lineage helper), 10.3 (evidence API), 10.4 (TopicEvidenceDrawer), 10.5 ("+ new (merged)" label)

---

## 1. Problem

Epic 10 shipped traceability at the data layer (lineage helpers, evidence API, evidence drawer). But the Timeline grid — the project's "bird's-eye view" — still presents each merge-result topic as a single row with no visible trace of the archived ancestors that formed it. The user has to open the Evidence Drawer to see lineage, losing the spatial context of the grid.

Two specific gaps this story closes:

**Gap A — Item-level provenance.** When a cell for "Topic X at Call 3" shows follow-ups `[Review by Friday, Spike GraphQL, Finalize RFC]`, the user can't tell which of those items was raised in Call 1 vs Call 2 vs Call 3. The cell shows the final-state UNION of all accumulated items; their origin is hidden.

**Gap B — Ancestor-row visibility in the grid.** M:N-merged topics (e.g. "API Strategy" created in Call 2 by merging "REST API" + "GraphQL API") have archived-ancestor rows that are either hidden by default or, when "Show archived" is toggled on, rendered as independent bottom-of-grid rows with no visual connection to their merge target. The lineage is technically present but spatially fragmented.

## 2. Goals

1. Each follow-up/decision item in a Timeline cell shows a compact pill (`C1`, `C2`, …) identifying the call that originally contributed it. Hover reveals the full call title.
2. Merge-result topic rows gain a chevron (▸/▾) that toggles indented, tree-nested ancestor rows directly beneath, preserving full per-cell fidelity and visually attaching the archived history to its merge target.
3. The same provenance pills appear in the `TopicEvidenceDrawer`'s per-call item lists — consistent visual language across Timeline + Drawer.
4. Archived-ancestor rows support full interactive parity (Evidence Drawer, cell expand, "Show evidence" link) — a user exploring lineage has the same tools as for live topics.

## 3. Non-Goals

- **Fuzzy item matching.** Exact-string only. Reworded items ("Spike GraphQL" → "GraphQL spike") fall back to `?` pill, which is acceptable for a first cut. Upgrade later if warranted.
- **Multi-level lineage chains in the grid.** An ancestor can itself be a merge-result (chain of merges). For this story, we render the direct parents only — not the parent-of-parent indent. The Evidence Drawer covers deep chains.
- **Fuzzy or semantic provenance.** Only exact-string match against the topic's own `topic_updates` history.
- **Mobile layout.** Timeline grid is already desktop-only; this story preserves that constraint.
- **Database migrations.** Entirely a read-layer + UI change.

## 4. Decisions (from brainstorming 2026-04-21)

| # | Decision | Choice |
|---|---|---|
| Q1 | Where pills appear | All views: Timeline cells (collapsed + expanded) + `TopicEvidenceDrawer` item lists |
| Q2 | Item-to-call matching | Exact-string only, `?` fallback for unmatched items |
| Q3 | Ancestor layout | Indented tree-nested rows (B in mockup) — preserves per-cell data, tree connectors `├─` / `└─` |
| Q4 | Visibility | Per-topic chevron (▸) on merge-result rows; global "Show archived" becomes "Expand all lineage" |
| Q5 | Interaction | Full parity — archived ancestors support Evidence Drawer, cell expand, pills |

## 5. Architecture

### 5.1 Single lineage helper (backend extension)

A new service function in `backend/services/topics_service.py` (adjacent to `list_topics_timeline`):

```python
def get_ancestors_by_target(project_id: str, db) -> dict[str, list[str]]:
    """Return {merge_target_topic_id: [ancestor_topic_id, ...]} for all
    archived topics in the project whose merged_into_topic_id is set.
    Ancestors ordered by first_raised_call_id's created_at ascending.
    """
```

`list_topics_timeline` uses this helper to decorate each topic in its response:
- Active merge-result topic (`has_sources: True` from Story 10.5) gets an additional field `ancestor_topic_ids: list[str]`.
- Archived-ancestor topic gets `merge_call_id: str | None` — derived from `merged_into_topic_id` → look up merge-target's `first_raised_call_id`.

### 5.2 Evidence API unchanged

Provenance is computed client-side from data already in the timeline payload (each cell's `follow_up_items` + `decisions`). No new endpoint.

### 5.3 Frontend: pure provenance utility

**New file: `frontend/src/utils/provenance.ts`**

```typescript
type CellHistory = {
  call_id: string;
  follow_up_items: string[];
  decisions: string[];
};

/**
 * Resolve which call first contributed each item in `currentItems`.
 * Walks `history` chronologically (oldest first), returns the call_id of
 * the earliest call whose same-section array contained the exact string.
 * Returns null for items not found in any prior call (fallback to "?").
 */
export function resolveProvenance(
  currentItems: string[],
  history: CellHistory[],
  section: "follow_up_items" | "decisions",
): (string | null)[];
```

Pure function. Easily unit-testable. Called once per expanded cell's item list.

### 5.4 Frontend: shared pill component

**New file: `frontend/src/components/ProvenancePill.tsx`**

Small component rendering a compact pill:
- Props: `{ callId: string | null; callIndex: number | null; callTitle: string | null }`
- If `callId` is null → renders muted `?` pill, tooltip "Origin call not found in history (possibly reworded)"
- Otherwise → rounded pill with background color from 8-color palette cycled by `callIndex`, text `C{index+1}` (1-indexed for user), tooltip shows full call title

Palette shared with `TopicEvidenceDrawer` (already defined there — extract to a constant).

### 5.5 Frontend: Timeline row rendering

`frontend/src/components/TopicsTimeline.tsx` gains:

1. **Merge-result row**: renders a chevron button next to the topic name when `has_sources === true`. Chevron state tracked in component-level `expandedLineageIds: Set<string>`. Clicking toggles expansion.

2. **Ancestor rows (shown when expanded)**:
   - Rendered directly after the merge-result row, iterating `ancestor_topic_ids`
   - Topic name column: indent 16px, prefix `├─` or `└─` (last ancestor), strikethrough name, dimmed color
   - Cells: same component as regular cells, with these variants:
     - Cell at `merge_call_id` column: special `Merged ↗` badge + "→ folded into {merge-result name}" annotation
     - Cells past the merge column: muted "(archived)" text
     - Cells before the merge: regular cell rendering (summary, follow-ups with pills, decisions with pills)

3. **Cell rendering with pills**: both collapsed summary ("3 follow-ups (C1–C3)" — computed from unique origin calls) and expanded view (per-item pill) consume the new `ProvenancePill` component.

4. **Global "Show archived" toggle**: renamed to "Expand all lineage". Toggling on adds every merge-result topic's id to `expandedLineageIds`. Toggling off clears.

### 5.6 Frontend: Evidence Drawer pill integration

`frontend/src/components/TopicEvidenceDrawer.tsx` — the per-call `CallCard`'s follow-ups and decisions sections wrap each item with a `ProvenancePill` showing the card's own call. (Trivial case: pill always matches the card's call; keeps visual consistency.)

For the separate follow-up/decision aggregation in "lineage mode" — the cards are already per-call, so pills map directly.

## 6. Data flow

```
GET /api/projects/{id}/topics/timeline
  → list_topics_timeline
      → active_topics + archived_topics (existing)
      → ancestors_by_target = get_ancestors_by_target(project_id, db)  (new)
      → for each active merge-result topic:
          → attach ancestor_topic_ids = ancestors_by_target[topic.id]
      → for each archived topic:
          → attach merge_call_id = lookup(merged_into.first_raised_call_id)
      → return full timeline payload

Frontend:
  TopicsTimeline mounts
    → fetches timeline payload
    → renders rows (active + archived both indexed by id)
    → user clicks chevron on merge-result row:
        → expandedLineageIds.add(topicId)
        → render inserts ancestor rows from ancestor_topic_ids
        → each ancestor row uses its own data from archived topics list
    → user expands a cell:
        → provenance utility walks the topic's history (cells ordered by call_date)
        → resolves origin call per item
        → renders items with ProvenancePill
```

## 7. Error handling

- **No ancestors (topic not a merge-result)**: `has_sources === false` → no chevron, no ancestor rows. Current behavior.
- **Ancestor data inconsistency (ancestor ID exists but topic row not in archived list)**: skip that ancestor ID silently, log warning.
- **Item matching fails (reworded)**: null returned from `resolveProvenance` → `?` pill rendered. User sees acknowledgment that origin is unknown; tooltip explains why.
- **Pre-Epic-10 topics lacking some fields**: defensive `?? []` fallback. Pills still render for items that do match; unmatched items get `?`.

## 9. Open questions

None after the 5-question brainstorm. All critical decisions are Q1–Q5 above.

## 10. Out of scope (explicit deferrals)

- Fuzzy item matching (LLM rewordings land as `?` pills)
- Multi-level lineage indentation (one level of ancestry shown; deeper chains accessible via Evidence Drawer)
- Mobile / small-screen layout
- Animating chevron expand/collapse (simple show/hide is fine for now)
- Keyboard navigation across the grid
