## Goal

`/projects/[id]/board` shows a live 4-column kanban board fetching real calls from the API. Users can create new calls via a modal. The board enforces the sequential call rule by disabling "New Call" when any call is not `done`.

---

## Visual Design (approved via mockup 2026-04-09)

**Color palette** (from `docs/superpowers/specs/2026-04-09-ui-shell-design.md`):

| Stage | Column label | Left-border + badge color |
|---|---|---|
| transcript | Get Transcript | `#0052cc` (blue) |
| artifacts | Artifacts | `#ff8b00` (orange) |
| topics | Topics | `#6554c0` (purple) |
| done | Done | `#36b37e` (green) |

**Call card:**
- White card, `border-radius: 4px`, `box-shadow: 0 1px 3px rgba(0,0,0,.12)`
- 3px left border in stage color
- Title (13px, semibold, `#172b4d`)
- Footer row: stage badge (colored pill) + `created_at` date (10px, `#97a0af`)
- Done cards: `opacity: 0.65` (read-only visual)
- Hover: elevated shadow

**"+ New Call" button:**
- Enabled (blue `#0052cc`): all calls are `done` or no calls exist
- Disabled (grey `#97a0af`): any call is not `done` — shows tooltip "Complete the active call first" on hover

**New Call modal:**
- Title: "New Call"
- Single field: "Call title" (text input, focused on open)
- Hint text: "The call will start in the 'Get Transcript' stage."
- Actions: Cancel (outlined) + Create (blue primary)

## Architecture

**Data fetching strategy:** Option A — full client component with `useEffect` fetch + refetch after create. Consistent with `Sidebar.tsx` pattern, no new dependencies.

**Board page** (`app/projects/[id]/board/page.tsx`):
- `"use client"`
- Reads `projectId` from `useParams()`
- `loadCalls()` → `callsAPI.list(projectId)` → sets `calls` state
- Computes `hasActiveCall = calls.some(c => c.kanban_stage !== "done")`
- Passes `calls` + `hasActiveCall` + `onCreated` to child components
- Loading state: subtle spinner in board area
- Error state: inline error message + retry button

## API additions to `client.ts`

```ts
export const callsAPI = {
  list: (projectId: string) =>
    proxyFetch<Call[]>(`/api/projects/${projectId}/calls`),
  create: (projectId: string, data: { title: string }) =>
    proxyFetch<Call>(`/api/projects/${projectId}/calls`, {
      method: "POST",
      body: JSON.stringify(data),
    }),
};
```

No new types needed — `Call` and `KanbanStage` already exist in `src/types/index.ts`.

## Acceptance Criteria (from story-3.2.md — all must pass)

- [ ] Project board page has two tabs: "Kanban" and "Topics" (Topics tab placeholder)
- [ ] Kanban view shows 4 columns: Get Transcript · Artifacts · Topics · Done
- [ ] Each call appears as a card in the correct column based on `kanban_stage`
- [ ] "New Call" button opens a create modal (title input)
- [ ] "New Call" button is disabled (with tooltip) when any call is not `done`
- [ ] Creating a new call calls `POST /api/projects/{id}/calls` and reloads the board
- [ ] Clicking a card navigates to `/projects/[id]/calls/[call_id]` (placeholder)
- [ ] Done calls show as read-only (faded) cards in the "Done" column

## Error handling

| Scenario | Behaviour |
|---|---|
| `GET /calls` fails on load | Inline error in board area + "Retry" button |
| `POST /calls` returns 409 | Should never fire (button disabled guard), but if it does: show error in modal, keep modal open |
| `POST /calls` network error | Show error in modal, keep modal open |
